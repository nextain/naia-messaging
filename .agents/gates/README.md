# 조건 스크립트

주기 작업이 모델을 부르기 전에 먼저 돌리는 싼 검사입니다.
`.claude/hooks/scheduled-task-gate.js` 가 예약 프롬프트의 `#gate:` 지시선을 보고 이곳을 찾습니다.

## 계약

인자는 `#gate: <이름> [인자...]` 의 이름 뒤 토큰이 그대로 넘어옵니다. 이름에 경로를 적을 수는
없고, 이 디렉터리의 `<이름>.mjs` `.js` `.cjs` `.sh` 중 먼저 찾은 것이 실행됩니다.

종료 코드가 전부입니다.

| 코드 | 뜻 | 훅의 행동 |
|---|---|---|
| 0 | 할 일이 있다 | 진행 |
| 1 | 할 일이 없다 | 이번 회차를 건너뛴다 |
| 그 외 | 판단 실패 | **진행**하고 stderr 로 알린다 |

첫 줄의 출력은 사람이 읽을 사유로 쓰입니다. 건너뛸 때는 왜 건너뛰는지 한 줄로 적어 주세요.

판단 실패에서 진행하는 쪽을 고른 이유는, 조건이 고장 나 조용히 모든 회차를 막으면 비용은
0 이 되지만 자동화가 죽은 것을 아무도 모르기 때문입니다. 온맘 게이트웨이가 그렇게 5일
침묵했습니다. 잘못 열리는 대가는 돈이고, 잘못 닫히는 대가는 침묵입니다.

## 상태

직전 관측이 필요한 조건은 `$XDG_STATE_HOME/naia/gates/<이름>.json` 에 씁니다. 저장소 안에
쓰지 않습니다 — 기기마다 다른 값이고 커밋될 것이 아닙니다.

## 있는 것

- `git-has-new-commits` — 지정한 ref 의 HEAD 가 지난 회차 이후 움직였는지
- `path-changed` — 지정한 경로들의 최신 수정 시각이 지난 회차 이후 움직였는지

## 새로 만들 때

모델을 부르지 않고 끝나야 의미가 있습니다. 네트워크 호출 하나, 파일 stat 몇 개, `git
rev-parse` 정도가 적당합니다. 30초를 넘기면 훅이 타임아웃으로 보고 진행시킵니다.

## 훅이 닿지 않는 주기 작업

systemd 타이머나 cron 이 모델 CLI 를 직접 부르는 경우에는 예약 관문 훅이 닿지 않습니다.
그쪽은 이미 프로세스가 뜬 뒤에야 훅이 돌기 때문에, 문맥 적재 비용을 이미 낸 상태입니다.

그런 작업은 `scripts/gate-run.mjs` 로 감쌉니다. 조건을 먼저 보고 할 일이 없으면 모델 CLI 를
아예 띄우지 않습니다. 모델 호출이 0 이라 절감이 가장 큽니다.

```
ExecStart=/usr/bin/node /var/home/luke/alpha-adk/scripts/gate-run.mjs \
    git-has-new-commits HEAD /var/home/luke/dev -- /path/to/run-triage.sh
```

건너뛸 때 종료 코드는 0 입니다. systemd 가 실패로 읽으면 그 유닛이 "Failed" 로 쌓여 진짜
실패와 구분되지 않습니다. 온맘 검사기가 15일간 발견을 보고했는데 `exit 1` 이 "Failed" 로
읽혀 아무도 안 본 사고가 있었습니다.

무엇을 했는지는 `$XDG_STATE_HOME/naia/gate-run.json` 에, 고장은
`$XDG_STATE_HOME/naia/gate-run.alerts.log` 에 남습니다.
